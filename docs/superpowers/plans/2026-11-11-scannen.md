# Scannen Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ein Button „Scannen“ im Ribbon-Tab Start öffnet einen Scan-Dialog (WIA). Die gescannten Seiten werden als PDF an den aktiven Tab angehängt oder als neues Dokument geöffnet.

**Architecture:** `ScanDienst` kapselt WIA (spät gebunden über `dynamic`, auf einem eigenen STA-Thread) und liefert Seitenbilder als PNG-`byte[]`. `ScanPdf` baut daraus mit PDFsharp ein PDF-`byte[]`. `ScanFenster` (FluentWindow) sammelt die Seiten über mehrere Durchgänge und gibt am Ende das PDF zurück. `MainWindow` entscheidet zwischen Anhängen und neuem Dokument und ruft dazu neue Methoden in `HauptViewModel.Scan.cs` auf.

**Tech Stack:** .NET 8 WPF, WPF-UI 4.3, WIA 2.0 (COM, `WIA.DeviceManager`), PDFsharp 6.2.4, SkiaSharp (über PDFtoImage vorhanden).

**Spec:** `docs/superpowers/specs/2026-11-11-scannen-design.md`

## Global Constraints

- Alles Deutsch: Code, Bezeichner, Kommentare, UI-Texte.
- Keine Code-Datei über 500 Zeilen. Sonst `partial class` mit Dateinamen `Typ.Aspekt.cs`. `HauptViewModel.Befehle.cs` hat schon 446 Zeilen, neue VM-Methoden kommen deshalb in `HauptViewModel.Scan.cs`.
- Byte-Array-Modell: Dokumentänderungen nur über `PdfDokumentDienst.Transformieren`, kein `PdfDocument` über Operationen hinweg aufbewahren.
- Keine neue NuGet-Abhängigkeit, keine COM-Interop-DLL in der Auslieferung. WIA wird spät gebunden über `Type.GetTypeFromProgID("WIA.DeviceManager")` + `dynamic` angesprochen.
- MSIX: nur `runFullTrust`, keine neue Capability.
- Standardwerte: Graustufen, 300 DPI, A4, Helligkeit 0, Kontrast 0. Papierformate: A4, A5, Letter.
- Einstellungen: `%AppData%\Roaming\perPDF\scan.json`, Muster `Services/FensterEinstellungen.cs`.
- Kein Profil, kein Dateityp, kein „separate Dateien“, kein Ausschnitt, keine OCR.
- Es gibt kein Testprojekt. Verifizieren heißt: `dotnet build PdfEditor.sln -c Release` ohne Fehler, dann die App von Hand mit einem echten Scanner durchspielen. Reine Logik bekommt eine `Debug.Assert`-Selbstprüfung (Task 2).

## Review Focus

1. **Einzug liefert 0 Seiten (Fach leer):** Hinweis „Kein Papier im Einzug“, kein leerer Durchgang, keine Frage „Weitere Seiten?“. → Manuelle Prüfung in Task 4.
2. **Fehler mitten im Einzug** (Stau, Deckel offen nach Seite n): Die n Seiten bleiben erhalten, die Meldung nennt n. → Manuelle Prüfung in Task 4 (Einzug mit Papierstau provozieren oder Scanner während des Einzugs ausschalten).
3. **Gespeicherter Scanner fehlt** (abgesteckt, umbenannt): Der Dialog öffnet trotzdem und wählt den ersten verfügbaren Scanner. Gibt es gar keinen, erscheint die Meldung „Kein Scanner gefunden“ und Vorschau/Scannen sind gesperrt. → Manuelle Prüfung in Task 4.
4. **Anhängen an ein Dokument mit ungespeicherten Annotationen/Formularwerten:** Diese bleiben erhalten, die Scan-Seiten erscheinen am Ende, das Dokument ist als geändert markiert. → Manuelle Prüfung in Task 5.
5. **UI bleibt bedienbar während des Scans:** Das Fenster zeigt nie „Keine Rückmeldung“, die Buttons sind gesperrt, und es ist sichtbar, dass gerade gescannt wird. → Manuelle Prüfung in Task 4.

### Task 1: Scan-Einstellungen und WIA-Dienst

**Files:**
- Create: `PdfEditor/Services/ScanEinstellungen.cs`
- Create: `PdfEditor/Services/ScanDienst.cs` (bei >500 Zeilen in `ScanDienst.Eigenschaften.cs` aufteilen)

**Interfaces:**
- Produces:
  ```csharp
  public enum ScanQuelle { Flachbett, Einzug, EinzugDuplex }
  public enum ScanFarbe { Farbe, Graustufen, Schwarzweiß }
  public enum ScanPapier { A4, A5, Letter }

  public class ScanZustand   // JSON-serialisiert
  {
      public string? ScannerId { get; set; }
      public ScanQuelle Quelle { get; set; } = ScanQuelle.Flachbett;
      public ScanPapier Papier { get; set; } = ScanPapier.A4;
      public ScanFarbe Farbe { get; set; } = ScanFarbe.Graustufen;
      public int Dpi { get; set; } = 300;
      public int Helligkeit { get; set; }   // -100..100
      public int Kontrast { get; set; }     // -100..100
  }
  public static class ScanEinstellungen
  {
      public static ScanZustand Laden();            // nie null; Fehler → new ScanZustand()
      public static void Speichern(ScanZustand z);  // Fehler ignoriert
  }

  public record ScannerInfo(string Id, string Name);
  public class ScanFehler(string meldung, int bisherigeSeiten) : Exception(meldung)
  { public int BisherigeSeiten { get; } = bisherigeSeiten; }

  public static class ScanDienst
  {
      public static List<ScannerInfo> ScannerAuflisten();
      public static List<ScanQuelle> QuellenErmitteln(string scannerId);
      // Liefert je Seite ein PNG; bei Einzug alle Blätter bis „Fach leer“.
      // Läuft intern auf eigenem STA-Thread; onSeite wird pro fertiger Seite
      // (auf dem STA-Thread) aufgerufen, damit Seiten vor einem Fehler erhalten bleiben.
      public static Task ScannenAsync(string scannerId, ScanZustand einstellungen,
                                      Action<byte[]> onSeite, CancellationToken ct = default);
  }
  ```

- [ ] **Step 1: `ScanEinstellungen` schreiben.** Kopie des Musters aus `FensterEinstellungen` mit Dateiname `scan.json`. Die Enums werden als Zahlen serialisiert (Standard von `System.Text.Json`).
- [ ] **Step 2: `ScannerAuflisten`.** `DeviceManager.DeviceInfos`, nur `Type == 1` (WiaDeviceType.ScannerDeviceType). `Id = DeviceID`, `Name = Properties["Name"].Value`. Ist WIA nicht verfügbar (ProgID fehlt), kommt eine leere Liste zurück.
- [ ] **Step 3: `QuellenErmitteln`.** Gerät verbinden und Eigenschaft `3086` (WIA_DPS_DOCUMENT_HANDLING_CAPABILITIES) lesen. Ist Bit `0x002` gesetzt (FLATBED) oder fehlt die Eigenschaft → `Flachbett`. Bei Bit `0x001` (FEEDER) → `Einzug`. Bei Bit `0x004` (DUPLEX) → zusätzlich `EinzugDuplex`. Ergibt das keine Quelle, wird mindestens `Flachbett` zurückgegeben.
- [ ] **Step 4: `ScannenAsync`.** Auf einem neuen `Thread` mit `SetApartmentState(STA)`, Ergebnis über `TaskCompletionSource`:
  - Geräteeigenschaft `3088` (DOCUMENT_HANDLING_SELECT) setzen: Flachbett `2`, Einzug `1`, Duplex `1|4 = 5`. Bei Einzug zusätzlich `3096` (PAGES) = `1`, falls vorhanden.
  - Item `Items[1]`, Eigenschaften setzen, jeweils nur, wenn die Eigenschaft existiert, und auf den erlaubten Bereich geklemmt (`SubTypeMin/Max`):
    - `6146` Intent: Farbe 1, Graustufen 2, Schwarzweiß 4
    - `6147`/`6148` DPI
    - `6154`/`6155` Helligkeit/Kontrast, von −100..100 auf Min..Max skaliert
    - `6149`/`6150` Startposition 0
    - `6151`/`6152` Ausdehnung in Pixeln = Papiermaß in Zoll × DPI (A4 8,27×11,69; A5 5,83×8,27; Letter 8,5×11), auf die Maximalwerte geklemmt
  - Schleife: `item.Transfer(WiaFormatPNG = "{B96B3CAF-0728-11D3-9D7B-0000F81EF32E}")` → `ImageFile.FileData.get_BinaryData()` als `byte[]` → `onSeite`. Bei Flachbett nach 1 Seite Ende. Bei Einzug weiter, bis eine `COMException` kommt:
    - HResult `0x80210003` (WIA_ERROR_PAPER_EMPTY) und mindestens 1 Seite → normales Ende.
    - HResult `0x80210003` und 0 Seiten → `ScanFehler("Kein Papier im Einzug.", 0)`.
    - Jede andere HResult → `ScanFehler`, Meldung nach HResult: `0x80210002` Papierstau, `0x80210006` Scanner belegt, `0x80210005` Scanner offline/aus, sonst „Scanfehler (0x…)“. Dazu die bisherige Seitenzahl.
  - Vor jeder Seite `ct` prüfen.
- [ ] **Step 5: Bauen.** Run: `dotnet build PdfEditor.sln -c Release` → Expected: Build succeeded, 0 Fehler.
- [ ] **Step 6: Commit.** `git add PdfEditor/Services/Scan*.cs && git commit -m "Scannen: WIA-Dienst und Einstellungen"`

### Task 2: PDF aus Scan-Seiten

**Files:**
- Create: `PdfEditor/Services/ScanPdf.cs`

**Interfaces:**
- Consumes: `ScanFarbe` (Task 1)
- Produces: `public static class ScanPdf { public static byte[] Erstellen(IReadOnlyList<(byte[] Png, ScanFarbe Farbe, int Dpi)> seiten); }`. Jede Seite trägt ihre eigene Farbe und DPI, weil sich die Einstellungen zwischen Durchgängen ändern können.

- [ ] **Step 1: Selbstprüfung schreiben** als `[Conditional("DEBUG")] internal static void Selbsttest()` in `ScanPdf.cs`, aufgerufen einmal aus `App.OnStartup` (nur Debug):
  ```csharp
  // 2480×3508 px bei 300 DPI = A4 → 595,3 × 842,0 pt
  var png = TestPng(2480, 3508);   // SKBitmap weiß, als PNG kodiert
  byte[] pdf = Erstellen([(png, ScanFarbe.Graustufen, 300), (png, ScanFarbe.Graustufen, 300)]);
  using var d = PdfReader.Open(new MemoryStream(pdf), PdfDocumentOpenMode.Import);
  Debug.Assert(d.PageCount == 2);
  Debug.Assert(Math.Abs(d.Pages[0].Width.Point - 595.3) < 1);
  Debug.Assert(Math.Abs(d.Pages[0].Height.Point - 842.0) < 1);
  Debug.Assert(pdf.Length < 600_000);   // Größenziel Graustufen
  ```
- [ ] **Step 2: Debug-Build starten und prüfen, dass die Assertion fehlschlägt** (Methode wirft `NotImplementedException`). Run: `dotnet run --project PdfEditor -c Debug` → Expected: Assert-/Exception-Dialog beim Start.
- [ ] **Step 3: `Erstellen` implementieren.**
  - Pro Seite: PNG mit SkiaSharp dekodieren.
    - Farbe/Graustufen → JPEG Qualität 85. Bei Graustufen vorher in `SKColorType.Gray8` umwandeln, damit das JPEG einkanalig wird.
    - Schwarzweiß → PNG Gray8 (Flate, verlustfrei; Ausweichlösung laut Spec).
  - `XImage.FromStream`, Seite mit Breite/Höhe = Pixel ÷ DPI × 72 pt, Bild füllend zeichnen.
  - Die Seitenreihenfolge entspricht der Listenreihenfolge.
- [ ] **Step 4: Debug-Build starten** → Expected: App startet ohne Assert-Dialog.
- [ ] **Step 5: Commit.** `git commit -m "Scannen: PDF aus Seitenbildern"`

- [ ] **Step 1: Layout** nach Vorbild `ZusammenführenFenster` (Titel „Neuer Scan“, ca. 760×560, nicht vergrößerbar ist nicht nötig). Zweispaltig:
  - **Links:**
    - „Scanner: {Name}“ + Button „Ändern…“. Der Button öffnet ein kleines Auswahlfenster oder `ContextMenu` mit `ScannerAuflisten()`. Die Wahl des Implementierenden, ein ComboBox-Popup reicht.
    - Trennlinie
    - Quelle (ComboBox, nur `QuellenErmitteln`; Anzeigetexte „Flachbett“, „Einzug (einseitig)“, „Einzug (beidseitig)“)
    - Papierformat (A4/A5/Letter)
    - Trennlinie
    - Farbmodus (Farbe/Graustufen/Schwarzweiß)
    - Auflösung (ComboBox 150/200/300/600)
    - Trennlinie
    - Helligkeit und Kontrast, jeweils Slider −100..100 + `ui:NumberBox`
  - **Rechts:** `Border` mit `Image` (Uniform), darunter Textzeile „{n} Seite(n) gescannt“.
  - **Unten rechts:** „Vorschau“, „Scannen“ (Primary), „Abbrechen“.
- [ ] **Step 2: Laden.**
  - `ScanEinstellungen.Laden()` in die Steuerelemente übernehmen.
  - Scanner = gespeicherte Id, falls in `ScannerAuflisten()` vorhanden, sonst der erste.
  - Gibt es keinen Scanner: Text „Kein Scanner gefunden“, Vorschau/Scannen gesperrt.
  - Bei jedem Scannerwechsel die Quellen neu ermitteln. Ist die gespeicherte Quelle nicht verfügbar, die erste nehmen.
- [ ] **Step 3: Vorschau.**
  - Nur aktiv bei `Flachbett`, sonst Tooltip „Vorschau nur mit Flachbett möglich“.
  - Scannt mit denselben Einstellungen, aber `Dpi = 75`, und zeigt das Bild. Es wird nicht gesammelt.
- [ ] **Step 4: Scannen.**
  - Während des Laufs alle Eingaben/Buttons gesperrt, ein `ui:ProgressRing` oder Text „Scannt…“ sichtbar.
  - `onSeite` hängt per `Dispatcher.Invoke` an die Liste `_seiten` an und zeigt die Seite in der Vorschaufläche.
  - Bei `ScanFehler` erscheint `MessageBox` mit der Meldung. Bei `BisherigeSeiten > 0` wird ergänzt: „Die {n} gescannten Seiten wurden übernommen. Bitte die restlichen Blätter neu einlegen.“
  - Danach, wenn der Durchgang mindestens 1 Seite lieferte, `MessageBox` „{gesamt} Seite(n) gescannt. Weitere Seiten scannen?“ mit Ja/Nein:
    - **Ja:** Der Dialog bleibt offen, die Einstellungen sind wieder bedienbar.
    - **Nein:** `Ergebnis = ScanPdf.Erstellen(_seiten)`, Einstellungen speichern, `DialogResult = true`.
  - `_seiten` ist eine `List<(byte[] Png, ScanFarbe Farbe, int Dpi)>`. Jede Seite speichert die Farbe und DPI ihres Durchgangs.
- [ ] **Step 5: Abbrechen / Schließen.** Bei `_seiten.Count > 0` erst die Rückfrage „Gescannte Seiten verwerfen?“ (Ja/Nein). Das gilt auch für das X in der Titelleiste (`Closing`). Während eines laufenden Scans ist Schließen gesperrt.
- [ ] **Step 6: Bauen und von Hand prüfen** (Fenster vorerst über einen temporären Aufruf oder direkt nach Task 5). Dabei die Punkte 1, 2, 3 und 5 aus dem Review Focus durchgehen sowie Flachbett mit 1 Seite und 2 Durchgängen. Hell- und Dunkelmodus.
